# Jolt feature qualification

This matrix is an acceptance checklist, not a roadmap-completion claim. `Verified` requires a public AZ-facing API, native implementation,
focused unit coverage, and reflection or component coverage where the feature is authorable. A green aggregate test target alone does not
change a row to `Verified`.

## Integration

| Area | Status | Evidence or remaining gate |
|---|---|---|
| Source dependency | Verified | JoltPhysics 5.6.0 is pinned and built privately through `JoltNative.cmake`. The native target, headers, and ABI definitions are implementation details and are not published through a find module or `3rdParty::Jolt`. Source and installed modular/monolithic consumers use only the Gem's AZ-facing API. The complete patch applies to a pristine archive and reverses cleanly from a patched tree. |
| Native API boundary | Verified | Public headers expose no `JPH` types. Native ownership and conversion remain in `Source/Jolt`. |
| Standalone provider | Verified | The Gem owns its system, worlds, handles, ticking, components, buses, scripting, cooking, and events without registering AzPhysics singletons. |
| Runtime and editor modules | Verified | Runtime, editor, scene-builder, unit-test, benchmark, and installer targets build independently. |

| Windows validation | Verified | The CPU-only Hair checkpoint passes MSVC Profile and Release builds with 169 runtime and isolated public-header tests, 38 editor tests, and 4 builder tests in each configuration. Profile `Editor` and `AssetProcessor` build from the current target graph, and the focused null-renderer `Jolt_CpuHair` scenario passes. The active solution contains no GPU Hair target, and the generated Jolt runtime, editor, and test projects contain no Atom or GPU-backend dependency. Previous performance and non-Hair evidence remains historical until rebuilt from the current revision. |

## Determinism and performance gates

- Cross-platform deterministic compilation, precise floating-point behavior, no contraction, deterministic worker scopes, canonical query and
  event ordering, callback-state fingerprints, and snapshot revision checks are mandatory shipping defaults.
- Optional body simulation counters are disabled by default. Both disabled and `LY_JOLT_ENABLE_SIMULATION_STATISTICS=ON` builds must pass.
- Release benchmark reports require 30 repetitions, matching workload signatures and policies, median parity, bootstrap bounds, tail bounds,
  and coefficient-of-variation checks. Profile captures are diagnostic and never substitute for Release timing.
- Assembly inspection must confirm that retained hot-path helpers inline, do not allocate, do not call CRT nextafter helpers, and preserve SIMD
  code generation. Any performance-sensitive determinism change requires a before-and-after diagnostic capture.
